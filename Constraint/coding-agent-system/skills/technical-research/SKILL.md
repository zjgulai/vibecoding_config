# Technical Research

用能对该事实负责的一手材料回答技术问题：官方文档、规范、维护者发布、源码或正式 API 定义。二手资料可用于发现线索，但不能单独支撑结论。

## Scope and evidence

1. 先界定要回答的具体问题、适用产品/组件与所需版本或日期。已有上下文足够时，不为了“多找来源”扩大检索。
2. 为每个关键主张追到拥有该主张的一手来源。记录来源、访问日期，以及材料所对应的版本、发布日期或生效日期；无法确认时标为未知。
3. 分开输出：`事实`（由来源直接支持）、`推断`（由事实得出的结论）和`未知`（仍会改变答案的缺口）。来源冲突时展示冲突，不用偏好的一个悄悄覆盖另一个。
4. 默认在回答中给出简短发现和可访问来源。只有用户要求，或项目已有约定要求时，才把研究写入仓库文件；写入前遵循其指定路径和格式。

## Completion criterion

回答能让读者区分已证实的技术事实、基于它们的建议与尚未核实项，并能回到一手来源复查关键结论。

## Authorization boundary

研究不自动授权扩展网络访问、调用外部服务、下载/安装内容、写仓库文件、修改配置、提交或发布。无法在现有权限内取得所需一手证据时，报告缺口并请求明确方向。
