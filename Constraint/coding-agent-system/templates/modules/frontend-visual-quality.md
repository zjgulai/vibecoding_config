# Frontend Visual Quality 模块

## 触发范围

当任务改变用户可见页面、组件、样式、交互、响应式布局或可访问性时启用。纯数据层或无可见行为的改动无需加载本模块。

## 先发现项目事实

- 确认目标页面、入口路由、用户流程、支持的 viewport、主题和浏览器范围。
- 判断界面属于任务型产品、营销/品牌、专家高密度工具或安全关键流程；识别主操作、次要操作和高风险操作。
- 确认输入方式、信息密度和使用频率，并记录可比较的同屏主操作、正文、表单和相邻控件作为基准。
- 查找现有 design tokens、组件库、字体、图标、spacing、颜色、动效和内容规范；优先复用已有视觉语言。
- 记录图标来源：优先项目现有图标家族，其次项目已可用的系统符号或行业通用隐喻；不得为单页新增依赖。
- 从依赖、scripts、CI 和测试目录确认运行、组件测试、端到端测试、截图或视觉回归工具。
- 检查相关页面当前状态及可复用组件，记录 loading、empty、error、disabled、focus 和 overflow 等状态。
- 如果需求只给出审美方向而未给出品牌或交互约束，先说明关键假设，不自行引入新设计系统。

## 视觉显著性、尺寸与图标

- 任务型界面默认克制；营销、品牌、关键警告和不可逆动作可因职责加强表达，但必须有规格、任务或风险依据。
- 尺寸和间距优先复用 design tokens、组件规格和平台惯例，再结合 viewport、输入方式、密度、频率和层级选择；不得仅靠放大建立层级。
- 当前主任务中的辅助入口、设置、开关和工具按钮默认次级但仍可发现；若其本身是主任务，或涉及安全、隐私、无障碍或关键状态，则按实际优先级处理。
- 常见动作复用项目既有组件/图标家族、系统符号或行业通用隐喻；不混用家族，不为单页新增依赖；歧义、低频或高后果动作配可见文字。
- Icon-only 控件必须具备正确语义、accessible name、可见 focus、明确状态和足够命中区；装饰图标不得进入 accessibility tree。
- 静止态优先通过位置、分组、排版、间距、对比、分隔和状态建立层级；颜色、hover、tooltip 和动效只能补充，不能成为核心语义的唯一通道。
- 没有任务、平台或品牌依据时，避免夸张尺寸、重色块、过度圆角、厚边框、强阴影和装饰性渐变。

## 最小质量门槛

- 建立清晰的信息层级和主操作路径，保持与项目现有品牌、组件和内容密度一致。
- 覆盖目标范围内的窄屏与宽屏布局，避免截断、意外横向滚动、重叠、不可达操作和布局跳动。
- 交互元素必须可键盘操作，具备可见 focus、正确语义、可读标签和足够的状态反馈；不只依赖颜色表达含义。
- 实现并检查任务涉及的 loading、empty、error、disabled 和成功状态；动效应服务于理解并尊重项目既有 reduced-motion 策略。
- 不用硬编码补丁绕开 design tokens，不为单页引入新的组件库、字体或图标依赖。

## UI 消融式删减检查

- 基线为已满足 UI acceptance 的同一页面、同一 viewport、主题、状态和任务。
- 候选只来自本轮新增容器、装饰、强调、控件、交互步骤或抽象；逐项隐藏/移除比较，不同时删多个变量。
- 可发现性、可读性、语义、visible focus、对比度、命中区、状态反馈和风险表达是保护边界。
- 「视觉更少」或截图更干净不是单独 oracle；删减后仍需实际同屏验证。
- 输出删除项、保留项、依据、复验结果和未验证范围。

## 验证命令与视觉检查

1. 从仓库已有 scripts 和文档启动正确页面，只使用已确认的包管理器与命令。
2. 运行相关组件或端到端测试；共享组件、路由或构建配置变化时追加项目已有的 lint、typecheck 与 build。
3. 在任务要求的 viewport、主题和关键交互状态进行实际浏览器检查；若项目有截图或视觉回归基线，按既有流程进行同屏比较。
4. 记录实际检查的页面、viewport、主题、状态、同屏比较基准和结果；检查相对尺度、填充、对比、字重、边框、阴影、elevation 和信息密度。
5. 不触发 hover、tooltip 或动画时，确认主任务与关键状态仍可理解，次要控件未无依据地压过主操作；危险动作须有清晰标签、区分及适当的 undo、review 或 confirm。
6. 视觉调整后复验文字可读性、命中区、focus 和状态语义。没有启动实际页面并检查渲染时，不得声明视觉质量通过。
