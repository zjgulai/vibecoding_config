# M03：用户研究与问题定义

## 用途

通过依赖感知访谈、已有反馈或真实研究资料，确定用户问题、上下文、现有行为和成功标准。

推荐 Skill：`product-discovery`、`grill-with-docs`、`grilling`、`to-questionnaire`。优先使用本地重写的 `product-discovery`；不要同时运行多个重复访谈器。

## 输入变量

```text
{{A00_PATH}}
{{A02_PATH}}
{{RESEARCH_MODE}} = stakeholder-interview | user-interviews | existing-feedback | planning-only
{{PARTICIPANT_SCOPE}}
{{AVAILABLE_EVIDENCE}}
{{OUTPUT_LOCATION}}
{{MODE}} = PLAN
```

## 可复制 Prompt

```text
你正在执行 M03「用户研究与问题定义」，默认 MODE=PLAN。

输入：
- A00_PATH: {{A00_PATH}}
- A02_PATH: {{A02_PATH}}
- RESEARCH_MODE: {{RESEARCH_MODE}}
- PARTICIPANT_SCOPE: {{PARTICIPANT_SCOPE}}
- AVAILABLE_EVIDENCE: {{AVAILABLE_EVIDENCE}}
- OUTPUT_LOCATION: {{OUTPUT_LOCATION}}
- MODE: {{MODE}}

授权边界：`MODE=PLAN` 只在回复中生成 A03 内容或拟落盘内容预览，不写任何文件。只有 `MODE=APPLY`，且适用的 G3 决定、G4 本地写入授权与 `OUTPUT_LOCATION` 的精确文件范围一致时，才可持久化；文件名或用户要求“生成文档”本身不构成写入授权。

方法：
1. 若用户已显式选择 product-discovery，加载它；有项目文档且需要同步领域词汇时可选 grill-with-docs。不要让 model-invoked primitive 代替用户对长访谈的同意。
2. 先复述 Outcome、User、Why now、Success、Constraints、Out of scope，请用户纠正。可从文件查明的事实先查，不用问题浪费用户时间。
3. 建立决策树，一次只问当前最有信息价值、前置条件已满足的一个问题。每问说明为何重要，并给出基于当前证据的推荐选项；没有真实差异时不提供伪选项。
4. 用户研究关注最近一次真实行为：触发情境、现有流程、替代工具、频率、成本、失败、权衡和实际后果。避免“你会不会使用”式未来假设和引导性提问。
5. RESEARCH_MODE=planning-only 时只产出招募/访谈计划，不声称已有用户结论。existing-feedback 必须保留原始证据位置并识别样本偏差。
6. 不收集不必要的 PII。引用用户原话时脱敏、限制长度、记录 consent/来源；不得把单个高情绪反馈当总体规律。
7. 对每个洞察区分 Observation、Interpretation、Assumption、Decision。若用故事线描述用户工作流，必须把故事线登记为可证伪的工作流假说，而不是用户事实；逐段记录现状观察、预期转变、可观察预测、反证和待验证项。叙事连贯不增加置信度。至少寻找一个反例或未覆盖用户群。
8. 需要第三方回答时，可生成 questionnaire，但不自动发送；需要 prototype 验证时把问题交给 M06。
9. 重大分支未关闭时继续访谈；达到饱和、预算上限或关键决定依赖缺席负责人时停止并记录原因。
```
