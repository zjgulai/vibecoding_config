# M06：原型与 UX 验证

## 用途

用隔离、一次性的实验回答一个高价值不确定问题。原型是学习工具，不是未经验证的生产实现。

推荐 Skill：`safe-prototyping` 或目标仓库 `prototype` 的问题驱动方法；UI 可选 `impeccable`、`frontend-design`、`ui-ux-pro-max`，只选一个主设计 Skill。

## 输入变量

```text
{{A04_PATH}}
{{A05_PATH}}
{{PROTOTYPE_QUESTION}}
{{PROTOTYPE_TYPE}} = logic | state-model | UI | AI-behavior
{{SANDBOX_LOCATION}}
{{TEST_USERS_OR_FIXTURES}}
{{MODE}} = PLAN | APPLY
{{G4_APPROVAL}} = NONE 或当前原型的精确本地写入授权
{{ALLOWED_FILES_OR_SANDBOX}} = NONE 或允许的隔离目录/route 与文件范围
```

## 可复制 Prompt

```text
你正在执行 M06「原型与 UX 验证」。一次原型只回答一个决定问题。

输入：
- A04_PATH: {{A04_PATH}}
- A05_PATH: {{A05_PATH}}
- PROTOTYPE_QUESTION: {{PROTOTYPE_QUESTION}}
- PROTOTYPE_TYPE: {{PROTOTYPE_TYPE}}
- SANDBOX_LOCATION: {{SANDBOX_LOCATION}}
- TEST_USERS_OR_FIXTURES: {{TEST_USERS_OR_FIXTURES}}
- MODE: {{MODE}}
- G4_APPROVAL: {{G4_APPROVAL}}
- ALLOWED_FILES_OR_SANDBOX: {{ALLOWED_FILES_OR_SANDBOX}}

步骤：
1. 验证该问题是否会改变产品/架构/UX 决策，且不能通过已有事实更便宜地回答。若问题含多个变量，拆成优先级最高的一个。
2. 若 safe-prototyping 已安装，优先加载。UI 创作最多选择一个主设计 Skill；设计审查可以用第二个只读 Skill，但不要叠加多个风格指令。
3. 在动手前写假说、可观察预测、成功/失败阈值、时间盒、允许使用的数据和清理方式。
4. MODE=PLAN 只给实验设计。MODE=APPLY 仍必须先核验 G4_APPROVAL 与 ALLOWED_FILES_OR_SANDBOX；任一缺失、过期或与当前写入目标不匹配时，保持 PLAN、只输出实验设计并停止。通过后也仅在获批 sandbox/route 中构建；不得覆盖生产 route、使用真实客户数据、写生产数据库或自动建 branch/Issue。
5. Logic/state prototype 使用最少依赖和可分享的 deterministic fixture。UI prototype 先读取同屏页面、design tokens、组件、单一图标家族和内容密度；提供 2–3 个主要在结构、流程或层级上不同的方向，不把同一布局换颜色或装饰冒充备选。若强强调是实验变量，必须预先记录。
6. UI 检查单一用户任务、信息层级、loading/empty/error/disabled/success、窄屏/宽屏、键盘/focus、对比度、reduced motion 和文案真实性；记录静止态可理解性、图标理解、命中区和同屏相对视觉重量的证据。
7. AI behavior prototype 必须固定 prompt/model/config/fixture，记录 stochastic limitation；禁止用少量 cherry-picked 演示替代 eval。
8. 收集证据时区分观察与解释。真实用户测试需要 G0 数据/consent 边界；没有用户时明确写“expert/fixture evaluation”。
9. 在解释证据后、作出原型决策前，冻结 hypothesis、learning question、acceptance、viewport/fixture 与风险；只从本轮原型逐项移除不能帮助回答学习问题的交互、流程、容器和 UI 元素，并以相同任务及 accessibility/usability 复验。记录每项 remove/defer/retain 与依据；这不授权生产代码或外部写入。
10. 结束后选择：accept learning、revise、reject、need more evidence。生产实现只携带结论和约束，不复制一次性 hack。
11. 清理或隔离原型产物；保留必须有明确 owner 和到期条件。

输出 `A06-prototype-evidence.md`：

# A06 Prototype Evidence
## Metadata
## Facts
## Decisions
## Assumptions
## Open questions
## Risks and reversibility
## Acceptance evidence

## Decision question
## Hypothesis and falsifiable prediction
## Prototype boundary
- Included
- Deliberately omitted
- Sandbox/cleanup

## Variants or experiment design
UI 方向说明复用的同屏页面、design tokens、组件、单一图标家族和内容密度；方向须主要在结构、流程或层级上不同。强强调若作为变量，预先记录。
## Evaluation method and participants/fixtures
## Observations
## Interpretation
## Counter-evidence and limitations
## Ablation evidence
- Baseline: 首次满足的 hypothesis、learning question、acceptance、viewport/fixture、风险和方法。
- Candidate: 仅本轮原型中逐项检查的交互、流程、容器或 UI 元素。
- Trace: 该候选回答学习问题或保护必要质量的依据；无则写 NONE。
- Decision: remove | defer | retain。
- Verification: 相同任务与 accessibility/usability 复验的方法、结果和证据层级。
- Limitations: 未执行项、不可重建时序或残余风险。
## Accessibility/usability checks
记录静止态可理解性、图标理解、命中区和同屏相对视觉重量的检查方法与证据。
## Prototype decision
Accept | Revise | Reject | More evidence。

## Changes required in A04/A05
## Prototype disposition
Deleted | Isolated | Retained until <date/reason>。

## Handoff
### To M07
只传递经过证据支持的设计约束和仍未知项。

完成标准：原型回答了预先定义的问题；没有把视觉吸引力等同于用户价值；生产代码未依赖一次性原型；证据层级真实。
```
