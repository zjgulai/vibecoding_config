# M02：机会与市场调研

## 用途

检验“是否存在值得解决的问题”，收集市场、替代方案、技术可行性和反方证据。它不是用户访谈的替代品。

推荐 Skill：`technical-research`、目标仓库 `research` 的一手来源纪律、Spec Kit assessment/research 方法。

## 输入变量

```text
{{PRODUCT_HYPOTHESIS}}
{{TARGET_USERS}}
{{GEOGRAPHY_OR_MARKET}}
{{A00_PATH}}
{{A01_PATH}}
{{RESEARCH_BUDGET}}
{{ALLOWED_SOURCES}}
```

## 可复制 Prompt

```text
你正在执行 M02「机会与市场调研」，保持 MODE=PLAN。

输入：
- PRODUCT_HYPOTHESIS: {{PRODUCT_HYPOTHESIS}}
- TARGET_USERS: {{TARGET_USERS}}
- GEOGRAPHY_OR_MARKET: {{GEOGRAPHY_OR_MARKET}}
- A00_PATH: {{A00_PATH}}
- A01_PATH: {{A01_PATH}}
- RESEARCH_BUDGET: {{RESEARCH_BUDGET}}
- ALLOWED_SOURCES: {{ALLOWED_SOURCES}}

规则：
1. 先读取已有 Context/Charter，明确研究问题、决策用途、时间边界和停止条件。若 technical-research 已安装且技术/标准事实会改变结论，加载它。
2. 将问题拆成：目标用户与 job、现有行为/替代、痛点频率与强度、购买/采用阻力、市场结构、关键技术/法规约束、反方假说。
3. 优先一手来源：官方产品/定价/政策/文档、原始研究、公开数据、维护者资料。二手材料只用于发现线索，关键结论回到一手来源。
4. 新闻、价格、版本、法规、竞争产品能力等时效性事实必须写访问日期。不要把搜索摘要当来源。
5. 对竞争产品区分“公开承诺、文档能力、可观察行为、用户评价”；没有实测就不写成实测。
6. 不编造访谈、用户数量、市场规模、转化率或 TAM。需要估算时显示公式、输入来源、范围与敏感性，不制造伪精确值。
7. 主动寻找会推翻机会的证据：问题可能不频繁、已有替代足够好、切换成本过高、分发不可行、数据/法规限制、单位经济性不成立。
8. 标注 evidence gaps，并把必须由真实用户验证的问题交给 M03。桌面研究不能替代真实用户研究。
9. 不注册账号、不付费、不抓取受限/私人数据、不联系用户或竞争对手。

## Recommendation

给 M03 的访谈对象、关键未知项和禁止诱导的假说。
```
