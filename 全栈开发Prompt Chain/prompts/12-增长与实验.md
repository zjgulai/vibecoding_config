# M12：增长与实验

## 用途

把产品学习转成有因果识别、护栏和停止规则的增长实验。它不是“自动优化转化率”的黑箱。

推荐 Skill：PM Skills 的 experiment/metric/cohort 方法、Marketing Skills 的 activation/retention/CRO 方法；条件 Adapter：PostHog 或 GrowthBook 二选一。

```text
{{A04_PATH}}
{{A11_PATH}}
{{GROWTH_OBJECTIVE}}
{{TARGET_SEGMENT}}
{{EXPERIMENT_PLATFORM}}
{{TRAFFIC_AND_TIME_BUDGET}}
{{G5_READINESS_DECISION}} = NONE | GO | CONDITIONAL | NO-GO
{{G6_DESIGN_DECISION}} = NONE | Approved | Rejected
{{R3_ACTION_AUTHORIZATION}} = NONE 或本次对象级 launch 授权
{{MODE}} = PLAN | APPLY；默认 PLAN
```

## 可复制 Prompt

```text
你正在执行 M12「增长与实验」。默认只设计和评审实验，不创建或启动真实 experiment/flag/campaign。

输入：
- A04_PATH: {{A04_PATH}}
- A11_PATH: {{A11_PATH}}
- GROWTH_OBJECTIVE: {{GROWTH_OBJECTIVE}}
- TARGET_SEGMENT: {{TARGET_SEGMENT}}
- EXPERIMENT_PLATFORM: {{EXPERIMENT_PLATFORM}}
- TRAFFIC_AND_TIME_BUDGET: {{TRAFFIC_AND_TIME_BUDGET}}
- G5_READINESS_DECISION: {{G5_READINESS_DECISION}}
- G6_DESIGN_DECISION: {{G6_DESIGN_DECISION}}
- R3_ACTION_AUTHORIZATION: {{R3_ACTION_AUTHORIZATION}}
- MODE: {{MODE}}

方法：
1. 从 A04 metric tree 和 A11 生产学习开始。确认问题属于 acquisition、activation、retention、revenue、referral 或 support efficiency；不要用漏斗标签代替用户机制。
2. 写增长机制：哪类用户在什么时刻采取什么行为，为什么这会影响 outcome？列出反馈循环、瓶颈、负面外部性和可能被 gaming 的指标。
3. 提出可证伪假说：If intervention, then behavior/outcome, because mechanism。区分产品价值假说、分发假说和 measurement 假说。
4. 选择最便宜且能改变决定的测试：qualitative prototype、instrumentation validation、A/B、switchback、holdout、cohort 或 phased rollout。流量不足时不要强行 A/B。
5. 定义 unit of assignment、eligibility、exposure、primary metric、guardrails、analysis window、minimum detectable effect 的输入和停止规则。没有 baseline/variance/traffic 时标记无法计算，不填通用阈值。
6. 检查 sample ratio mismatch、novelty、multiple testing、peeking、seasonality、network effects、contamination、instrumentation changes 和 missing data。
7. 实验平台只选项目已经使用的一个。PostHog/GrowthBook 默认 read-only 或 draft；不要在聊天中粘贴 PAT，不自动创建账号、feature flag、experiment、rollout 或 publish。
8. 涉及 dark pattern、敏感用户、定价歧视、隐私、未成年人或高风险决策时，先做伦理/合规评审。
9. G6 只批准实验设计：platform/project、flag/experiment 名、variants、traffic、segment、start/stop、owner 和 rollback。G6=Approved 后必须停止，不能把设计决定当 launch 授权。
10. 结果解释预先写 decision rule：ship、iterate、stop、inconclusive。统计变化不自动等于用户价值或长期保留。
11. 真实 feature flag、experiment、rollout、campaign 或生产流量变更同时需要 MODE=APPLY、G5 readiness=GO/CONDITIONAL、G6 design=Approved 和 R3_ACTION_AUTHORIZATION。R3 授权必须逐项列出 Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry；缺少任一条件时只保留 draft，不 launch/publish。
```
