# M01：项目初始化与治理

## 用途

为新项目或现有项目建立最小治理结构、项目画像、能力路由和验证入口。不会擅自选择框架、安装依赖或覆盖已有配置。

推荐 Skill：`project-profile`、`writing-for-agents`；目标仓库 `setup-matt-pocock-skills` 仅作字段参考，不直接执行其 tracker 写入假设。

## 输入变量

```text
{{PROJECT_ROOT}}
{{A00_PATH}} = A00-context-pack.md
{{TARGET_PLATFORMS}} = codex, claude-code, deepseek-harness 的子集
{{EXPECTED_STACK}} = 已确认技术栈或 UNKNOWN
{{PROJECT_STATE}} = blank | existing | unknown
{{MODE}} = PLAN | APPLY
```

## 可复制 Prompt

```text
你正在执行 M01「项目初始化与治理」。

输入：
- PROJECT_ROOT: {{PROJECT_ROOT}}
- A00_PATH: {{A00_PATH}}
- TARGET_PLATFORMS: {{TARGET_PLATFORMS}}
- EXPECTED_STACK: {{EXPECTED_STACK}}
- PROJECT_STATE: {{PROJECT_STATE}}
- MODE: {{MODE}}

先读取 A00 和当前目录事实。若项目目录不是空目录，不得把它当新项目覆盖；若存在未知重叠变更，停止写入。

方法：
1. 若用户明确要求初始化/审计长期画像且 project-profile 已安装，先显式加载。创建 Agent 指令时可加载 writing-for-agents。
2. 识别规范源：项目入口、依赖清单、lockfile、构建/测试命令、schema/migration、CI、部署说明、生成文件和局部规则。
3. 只把跨多数任务稳定、无法从代码直接推断且会改变决策的内容放入常驻指令。长工作流进入 Skill，路径/技术栈约束进入局部规则，确定性阻断进入 hook/CI，实时外部能力进入白名单 MCP。
4. `A01` 的项目画像摘要不等于 `.agents/project-profile.md`。只有用户明确要求创建或更新长期画像时，才处理后者；否则只给 dry-run 和 `draft` 建议。
5. 长期画像必须逐域覆盖：业务与安全不变量、权威修改入口、必须同步变更的联动关系、Do NOT/受保护区域、可运行或可观察的 Definition of Done、权威资料与冲突顺序、路径级局部风险。每条标记 Fact/Decision/Not applicable，并使用唯一受控 `Source`：`path:<项目相对路径>`、`command:<可复现命令>`、`url:<http(s) URL>` 或 `user-confirmation:<YYYY-MM-DD>:<确认上下文>`。
6. 证据不足、存在会改变架构/数据/权限/安全/兼容/验收的缺口，或存在未决重大冲突时，长期画像必须保持 `draft`。只有七域均有带受控 Source 的合规结论时才可建议 `active`；Assumption/Open question 不得进入 active。
7. `x`、`N/A`、空白和无来源的“无”不是结论；fenced block、HTML comment/隐藏元素、零宽字符或双向控制字符属于隐藏非结构化内容，发现后整体拒绝 active，不得清洗后继续。
8. 新项目：先给目录与配置 dry-run；框架脚手架、联网、依赖安装和全局工具在动作前请求授权。现有项目：只提出最小增量，不重排全仓目录。
9. 不创建真实 tracker label，不连接 MCP，不写真实凭据，不 commit。Hook/CI 只在确定性规则、允许/拒绝路径和恢复方式都明确后提出。
10. Cursor 不是目标平台。Codex/Claude/DSH 的共享方法可放 `.agents/skills`，平台差异留在各自适配层；不要把互斥平台字段塞进同一入口。

输出 `A01-project-charter.md`：

# A01 Project Charter
## Metadata
## Facts
## Decisions
## Assumptions
## Open questions
## Risks and reversibility
## Acceptance evidence
## Project state and evidence
## Product and users
## Repository and module boundaries
## Data and security boundaries
## Authoritative commands
每个命令写仓库来源；未运行标记 not run。

## Instruction architecture
- User-level stable kernel
- Project router
- Local/path rules
- Skills
- Deterministic controls
- MCP adapters

## Project profile
逐域列 Facts、Decisions、Unknowns、Sources，给 draft/active 建议。

## Initialization plan
按 read-only preflight、dry-run、apply、validate 四段列出；所有联网/依赖/覆盖动作单列审批。

## Governance
- Definition of Done
- Documentation source of truth
- Memory candidate policy
- Change/review policy
- Expiry signals

## G0 result
通过/未通过、证据、仍受限的数据和动作。

## Handoff
列出可消费事实与必须先解决的未知项。

完成标准：方案不会覆盖非空目录，不伪造项目命令，治理层级无重复，所有外部或高影响动作仍处于审批前。
```
