# M05：领域模型与产品规格

## 用途

把已批准策略转成共享语言和可实现、可验收的产品规格。默认只形成本地规格内容预览，不落盘、不发布 tracker。

推荐 Skill：`domain-modeling`、`specification`；目标仓库 `to-spec` 只借鉴结构，不采用自动发布与标签行为。

## 输入变量

```text
{{A01_PATH}}
{{A03_PATH}}
{{A04_PATH}}
{{EXISTING_DOMAIN_DOCS}}
{{SPEC_OUTPUT}} = A05-product-spec.md
{{MODE}} = PLAN
```

## 可复制 Prompt

```text
你正在执行 M05「领域模型与产品规格」。本阶段不实现代码、不创建 Issue。

输入：
- A01_PATH: {{A01_PATH}}
- A03_PATH: {{A03_PATH}}
- A04_PATH: {{A04_PATH}}
- EXISTING_DOMAIN_DOCS: {{EXISTING_DOMAIN_DOCS}}
- SPEC_OUTPUT: {{SPEC_OUTPUT}}
- MODE: {{MODE}}

授权边界：`MODE=PLAN` 只在回复中生成规格内容或拟落盘内容预览，不写任何文件。只有 `MODE=APPLY`，且适用的 G3 决定、G4 本地写入授权与 `SPEC_OUTPUT` 的精确文件范围一致时，才可持久化；A04 approved 只允许进入规格决策，不自动授权落盘。

前置门：A04 必须处于 approved，或用户明确允许生成 draft spec。否则停止并列出缺失决定。

规格成熟度：从 A03/A04 读取工作流故事假说，并把它当作待验证输入而非需求事实。进入 M06 原型前，至少定义最小可观察行为、对应的 FR/RISK 和 AC；不得以「产品完成后再补 PRD」绕过规格。原型、实现或生产证据可以精化规格，但必须记录证据来源、变更原因和受影响的追踪关系，不得用事后规格掩盖原先偏差。

方法：
1. 若 domain-modeling/specification 已安装且用户显式请求相应产物，加载它们。先读取现有 CONTEXT、ADR、schema、接口和术语，不重复创建第二套词汇。
2. 将 Observation、Interpretation、Assumption、Decision 分开。识别 entities、value objects、states、invariants、commands、events、actors、权限边界和失败语义。
3. 用具体场景检验词义：正常路径、边界、失败、并发/重复请求、取消/恢复、权限不足和数据不完整。
4. 只有同时满足“重大、存在真实备选、长期难逆”时才建议 ADR；普通实现细节不写 ADR。
5. Spec 描述可观察行为，不写逐文件施工清单。为每个进入范围的故事假说分配 `SH-xxx`；每项必须形成 `SH-xxx -> FR-xxx/RISK-xxx -> AC-xxx` 追踪。每项 requirement 都必须对应 acceptance；每项 acceptance 必须追溯到 requirement 或明确风险。
6. User journey 按优先级拆分，并保证每个高优先级 journey 可以独立验证。Acceptance 优先用 Given/When/Then 或同等可执行场景。
7. 若规格包含 UI，记录界面类型、目标 viewport/输入方式、信息密度、使用频率、主操作、次要操作和高风险操作；把相对显著性、图标可识别性、静止态层级和状态反馈写成可观察 acceptance。不得写跨场景统一像素值、指定新图标库，或把实现风格伪装成需求。
8. 明确 loading/empty/error/permission/timeout/retry/partial success 等状态；适用时覆盖数据生命周期、AI 输出不确定性、人工接管和滥用场景。
9. 定义 public test seams，但若新增 seam 会实质改变架构，则标记到 G3，不替用户决定。
10. 未决项不可用“业界最佳实践”猜测填平；它们保持 Open question 并阻塞相应 requirement。
11. 默认只输出本地 A05 的内容预览，不落盘。符合上述 APPLY 写入边界时才可写入本地 A05；真实 tracker、label 或外部发布必须另行给出预览、幂等策略和授权请求。

持久行为契约：每个高风险 requirement 都必须标明「可替换实现」「不可替换行为」「不变量或失败模式」「最小验证」和「兼容或恢复约束」。不得把 ADR、API、schema、权限或迁移决定隐藏在 implementation instruction 中。
```
