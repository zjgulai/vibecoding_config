# M10：发布与上线

## 用途

形成 release readiness、runbook、回滚和上线后验证。默认停在 no-side-effect readiness；部署执行需要另附于 G5 决策的对象级动作授权，通用“G5 通过”本身不构成授权。

推荐 Skill：本地 `release-readiness` 方法；`wizard` 只用于人类必须完成的步骤，并改写成不接触秘密的 runbook。平台特定部署 Skill 仅在项目已采用对应平台时启用。

## 输入变量

```text
{{PROJECT_ROOT}}
{{A09_PATH}}
{{RELEASE_TARGET}} = environment/service/version
{{RELEASE_STRATEGY}}
{{ROLLBACK_OWNER}}
{{MODE}} = PLAN | APPLY
{{G5_READINESS_DECISION}} = NONE | GO | CONDITIONAL | NO-GO
{{R3_ACTION_AUTHORIZATION}} = NONE 或本次对象级授权
```

## 可复制 Prompt

```text
你正在执行 M10「发布与上线」。默认只做 readiness，不执行部署。

输入：
- PROJECT_ROOT: {{PROJECT_ROOT}}
- A09_PATH: {{A09_PATH}}
- RELEASE_TARGET: {{RELEASE_TARGET}}
- RELEASE_STRATEGY: {{RELEASE_STRATEGY}}
- ROLLBACK_OWNER: {{ROLLBACK_OWNER}}
- MODE: {{MODE}}
- G5_READINESS_DECISION: {{G5_READINESS_DECISION}}
- R3_ACTION_AUTHORIZATION: {{R3_ACTION_AUTHORIZATION}}

流程：
1. 核验 A09 的 fixed range、blockers、验证新鲜度和未验证项。任何 Critical/Important blocker 未关闭时结论为 NO-GO。
2. 从仓库发现真实 build、migration、release、deploy 和 smoke 命令；不编造平台命令，不默认安装 CLI。
3. 明确 release unit、版本/commit、目标环境、依赖服务、配置、feature flags、数据/migration 顺序和责任人。
4. 区分 artifact build、staging validation、production deploy、traffic shift、post-deploy verification；前一步成功不证明后一步成功。
5. 设计 rollback/roll-forward：触发指标、决策人、数据兼容、不可逆步骤、恢复时间假设和验证方式。Migration 必须说明 old/new app 与 intermediate schema 的兼容窗口。
6. 最小权限处理 secret/config：只列变量名、来源系统和校验方法；不读取、粘贴、写入或回显值。需要人工 dashboard 操作时生成步骤化 runbook，不自动打开带敏感参数的 URL。
7. 定义上线后观测：availability、errors、latency、核心业务 outcome、AI quality/cost、queue/backlog、guardrails；每个指标写 source、baseline window、阈值依据和 owner。没有数据时不伪造阈值。
8. G5 是 readiness decision，不是执行授权。得到 G5=GO/CONDITIONAL 后必须停止，形成一份 R3 action proposal；MODE=PLAN、G5 非 GO/CONDITIONAL 或 R3_ACTION_AUTHORIZATION=NONE 时，只输出命令预览和 runbook，不 commit/push/tag/release/deploy/production read/write。
9. R3_ACTION_AUTHORIZATION 必须逐项列出 Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry；任一项缺失、过期、目标/副作用变化或超出授权时停止并重新请求授权。
10. 只有 MODE=APPLY、G5 readiness 已通过且 R3_ACTION_AUTHORIZATION 与当前动作完全匹配时才执行。每一步先验证 precondition，执行后读取权威状态；请求成功、CLI 退出 0 或 CI started 不等于发布成功。
11. 获授权发布后运行最小 production smoke 与指标检查，但不得使用真实用户敏感数据作为测试输入。未执行时，Execution receipt 必须写 `Not deployed / no production verification`。

输出 `A10-release-readiness.md`：

# A10 Release Readiness
## Metadata
## Facts
## Decisions
## Assumptions
## Open questions
## Risks and reversibility
## Acceptance evidence

## Release unit and target
## Quality gate summary
## Build/artifact provenance
## Configuration and secret names
只写名称、owner、验证方式。

## Migration and compatibility sequence
## Deployment strategy
## Rollback/roll-forward plan
## Observability and guardrails
## Runbook
每步写 Precondition、Action preview、Expected evidence、Failure response、Authorization。

## Readiness decision (G5)
GO | CONDITIONAL | NO-GO；写决定者、范围和过期条件。

## R3 action proposal and authorization
Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry。没有对象级授权时明确 `Not authorized`。

## Execution receipt
未执行时明确 `Not deployed / no production verification`。实际执行时记录权威返回、时间和验证层级，不记录秘密。

## Handoff
### To M11
版本、环境、expected change、监控窗口、关键指标、known risks、rollback trigger。

完成标准：readiness 与 deployment 不混淆；所有 R3 动作可单独批准；回滚和验证可操作；未部署时绝不写“已上线”。
```
