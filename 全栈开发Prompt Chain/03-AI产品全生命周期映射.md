## 1. 映射口径

本文把目标仓库固定提交
[9fe7e7a3bb352851b986725bab1c7cfb17610a97](https://github.com/vinvcn/mattpocock-skills-zh-CN/commit/9fe7e7a3bb352851b986725bab1c7cfb17610a97)
中的 36 个 Skill 映射到 M00–M13。清单事实、调用类型和逐项风险以
[01-目标仓库36个Skills逐项审计.md](./01-目标仓库36个Skills逐项审计.md)
为准；生命周期定义以
[00-研究方法与设计说明.md](./00-研究方法与设计说明.md)
为准。

映射遵守以下规则：

1. 每个 Skill 只有一个主归属。主归属表示它在本 Chain 中最主要解决的决策，不表示它只能在该模块使用。
2. 辅助模块可以重复。辅助关系不得绕过主模块的输入、审批门和产物契约。
3. 模块“覆盖”要求原仓方法能形成该模块的核心产物；只有相邻能力时仍记为“部分”或“缺失”。
4. stable、in-progress 和 internal 分开判断。in-progress 不因可读而视为可发布；internal 不进入产品开发公开能力。
5. 本映射是 E1–E4 静态设计证据。没有安装、运行或行为评测候选 Skill，因此不作 E5 有效性声明。
6. Skill 调用只选择方法，不授予文件、Git、tracker、secret、部署或生产权限。

覆盖状态定义如下：

| 状态 | 判定 |
|---|---|
| 覆盖 | 原仓至少有一个可形成核心产物的流程，主要缺口可由审批适配解决。 |
| 部分 | 原仓覆盖模块的一部分，但缺少关键证据、验证、治理或安全边界。 |
| 缺失 | 即使有 Skill 被唯一归入该模块，也只能提供通用或相邻方法，不能形成模块核心产物。 |

目标系统现有 15 个 Skill 均为 static-baseline；11 个 eval 只有 contract 证据，尚无行为验证。下文把它们视为可复用基线，不把“已存在”写成“已证明有效”。

### 2.1 目标系统 15 个 Skill 的作用边界

| 现有 Skill | 主要复用模块 | 边界 |
|---|---|---|
| project-profile | M00、M01 | 只记录 facts、decisions、not-applicable 和受控 Sources；draft 不等于 active。 |
| product-discovery | M03、M04 | 负责问题与产品决策，不替代真实市场、用户或生产证据。 |
| specification | M04、M05 | 规格写本地；不因规格完成而授权 tracker 或实现。 |
| domain-modeling | M03、M05 | 领域术语和 ADR 需要领域专家确认。 |
| safe-prototyping | M06 | 原型在隔离范围内回答一个问题，不进入生产。 |
| codebase-design | M07 | 提供 seam/interface/depth 方法，不自动实施架构改动。 |
| architecture-review | M07、M09 | 只读审查可以先行；高影响改动仍过 G3/G4。 |
| vertical-ticketing | M07 | 默认生成本地 ticket 草稿，不写真实 tracker。 |
| implementation-orchestration | M08 | 只编排获批 slice；不自动 commit、push 或开 PR。 |
| tdd | M08 | 在用户认可的 seam 上做 red→green，不用测试制造假通过。 |
| systematic-debugging | M08、M11 | 没有 red-capable loop 时停止猜测并索取证据或权限。 |
| two-axis-code-review | M09 | Standards 与 Spec 分开报告；不自动修复 finding。 |
| technical-research | M02、M07、M09 | 一手来源、范围、反证和停止条件必须显式；研究热度不是质量。 |
| writing-for-agents | M01、M13 | 用于文档和 Skill 设计，不替代行为 eval。 |
| memory-governance | M13 | 只返回 reject、more-evidence、trial 或 request-human-approval；不自动写、升格或删除长期记忆。 |

| AI Eval | ai-evaluation | 固定数据集、基线、离线评测、回归阈值 | Core 新增；结果写入 A09 | 原仓没有 AI-specific evaluator；模型分数受数据集、提示、模型版本和随机性影响。 |
| E2E、可访问性与性能 | browser-e2e、performance-accessibility | Microsoft Playwright CLI、axe-core、Lighthouse | Adapter；优先本地 server、fixture、只读 browser | 浏览器自动化可点击、提交和泄露 session；必须限制 origin、账户和写操作。 |
| CI 与发布 | release-readiness | GitHub starter-workflows、release-please | Supplement；只生成/审查 config 和 release plan | Workflow 模板依赖项目语言与权限；release automation 会创建 PR、tag 或 release。 |
| 部署与基础设施 | deployment-preflight | 平台官方 validate/plan/preview 模式 | Adapter；先确定实际平台，只保留 dry-run、diff、rollback | 通用自动部署 Skill 会混合安装、登录、项目链接、push、secret 和 production mutation。 |
| 可观测性 | production-investigation | Grafana MCP、Sentry MCP | Adapter；仅项目已使用时启用只读 tool allowlist | Logs、traces、replay 可能含 PII、secret 和 prompt injection；provider license 与权限模型不同。 |
| 事故响应 | incident-response | PagerDuty/Sentry/Grafana 的只读调查接口 | Supplement；Agent 整理证据，incident lead 决策 | ack、resolve、restart、rollback 和 status update 都是外部写入，不能由观察权限推导。 |
| 用户反馈 | user-feedback | PostHog insights/signals、只读 tracker triage | Supplement；原始反馈脱敏后聚类，并保留反例 | 自动主题归纳可能抹平少数用户、重复反馈或采样偏差；不能直接变成路线图。 |
| 产品分析与实验 | product-analytics、experiment-design | PostHog、GrowthBook | Adapter；只在既有埋点/feature flag 栈中使用 | 实验涉及流量、用户暴露、隐私、因果假设和生产开关；“指标上涨”不自动证明因果。 |
| 增长与内容 | growth-content | 原仓 writing-fragments/beats/shape 的方法 | Niche；内容生产与发布、归因、品牌审核分离 | 三项均为 beta，缺事实核验、分发、品牌和实验闭环。 |
| Skill 演进 | retrospective、skill-evolution | memory-governance、PostHog improving-mcp-tools 方法、AutoResearch 的固定目标/指标/日志/keep-discard | Core 新增；候选先进入 trial，人工批准后再晋升 | 自动改 Skill、Memory、AGENTS 或 Git 会放大偶然成功、污染全局规则并造成不可见行为漂移。 |

## 5. 系统级结论

原仓的强项是 M03–M08：澄清、领域建模、规格、原型、架构、切片、TDD、调试和 review。它不能被扩张解释为完整覆盖市场、AI Eval、安全、发布、部署、可观测性、事故、分析、实验、增长或自进化。

推荐架构不是“安装更多 Skill”，而是：

1. 以目标系统 15 个小 Skill 为前半生命周期 Core。
2. 为 M09–M13 新增职责单一的本地 Skill。
3. 把外部仓库降为固定版本的方法来源或最小 Adapter。
4. 让 A00–A13 和 G0–G6 承担跨 Skill 的状态与授权。
5. 把所有 commit、push、Issue、secret、deploy 和 production write 留在人类可见的动作级审批之后。

剩余不确定项：

- 外部候选的最终版本、stars、具体文件许可证和最近活动须由 05 的日期化来源表确认。
- 目标系统 15 个 Skill 和本 Chain 尚未做跨 Codex、Claude Code、DeepSeek Harness 的行为评测。
- M09–M13 的新增 Skill 在有 fixture、失败样例和撤回机制前只能是 draft。
