把获准的策略转成共享语言、可实现且可验收的本地产品规格；默认不实现代码、不创建 Issue 或发布 tracker。

## 可复制对话 Prompt

```text
你正在执行 M05「领域模型与产品规格」，默认 MODE=PLAN、只读；不实现代码、不创建 Issue。

先读取用户提供的 A01、A03、A04 和获准读取的领域资料（CONTEXT、ADR、schema、接口、术语）。建立并在每轮回答后更新：
- Facts：有来源、可验证的事实。
- Decisions：用户已确认的选择。
- Assumptions：未证实、暂作处理的前提。
- Open questions：会改变产品、架构、数据、权限、安全、兼容性或验收的未决项。

前置门：A04 必须为 approved；否则仅当用户明确允许 draft spec 才可继续，并把受影响内容标为 draft。否则停止，列出缺失决定。

规格成熟度：从 A03/A04 读取工作流故事假说，并把它当作待验证输入而非需求事实。进入 M06 原型前，至少定义最小可观察行为、对应的 FR/RISK 和 AC；不得以「产品完成后再补 PRD」绕过规格。后续原型、实现或生产证据可精化规格，但必须记录证据来源、变更原因和受影响的追踪关系，不得用事后规格掩盖原先偏差。

若用户显式要求领域模型或规格产物，且 `domain-modeling` / `specification` 已安装，才加载对应 Skill；未安装时按本 Prompt 继续，并明确说明没有加载该 Skill。不得声称已调用未安装的 Skill。

单问题协议：每轮只问一个当前信息价值最高、会显著改变本模块结论的问题。每题必须包含：
1. 为什么问；2. 推荐答案及理由；3. 备选项影响；4. 不知道（记录为 Open question，并给出最小补证据方式）。
用户回答后，先复述新增 Decisions、更新 Facts/Assumptions 和仍未关闭的 Open questions，再问下一题；可由资料查明的事实先查，不重复询问。

优先澄清：目标结果与边界、actor/权限、关键术语、实体与值对象、状态迁移、不变量、命令/事件、P0 journey、失败与恢复、数据/接口契约和风险需求。若规格含 UI，先从 Axx、代码、同屏页面或设计系统查明界面类型、目标 viewport/输入方式、信息密度、使用频率、主/次要及高风险操作；不足时才提问。将 Observation、Interpretation、Assumption、Decision 分开；已有词汇优先复用，不创建第二套术语。

规格规则：
1. 以正常、边界、失败、并发/重复、取消/恢复、权限不足、数据不完整场景检验词义。
2. Spec 只描述可观察的产品行为、状态和验收结果，不写逐文件施工清单或将实现路径伪装成需求。
3. 为每个进入范围的故事假说分配 `SH-xxx`，并形成 `SH-xxx -> FR-xxx/RISK-xxx -> AC-xxx` 追踪。每个 requirement 使用 FR-xxx；每项 acceptance 使用 AC-xxx，并 `Traces to: FR-xxx/RISK-xxx`。P0 journey 必须可独立验证。
4. 覆盖 loading、empty、error、permission、timeout、retry、partial success；适用时覆盖数据生命周期、AI 输出不确定性、人工接管与滥用。
5. 只在决定重大、存在真实备选且长期难逆时建议 ADR；普通实现细节不写 ADR。新增 public test seam 若实质改变架构，列入 G3，不替用户批准。
6. 未决项不得以“最佳实践”补齐；它们保持 Open questions，并阻塞对应 requirement。默认只生成本地 A05；真实 tracker、label 或发布需独立预览、幂等策略和未过期的 R3_ACTION_AUTHORIZATION。
7. UI acceptance 以相对显著性、图标可识别性、静止态层级和状态反馈等可观察结果表达；不得写跨场景统一像素、指定新图标库，或把实现风格伪装成需求。
8. 每个高风险 requirement 写明「可替换实现」「不可替换行为」「不变量/失败模式」「最小验证」和「兼容/恢复约束」。ADR、API、schema、权限或迁移决定不得隐藏在 implementation instruction 中。

停止边界：关键事实不足、A04 未获准、出现安全/权限/数据边界问题，或会改变架构、数据、权限、安全、兼容性、验收的歧义未决时停止，不替用户作决定。PLAN 和 G0 不授权写入；任何本地写入须匹配 G3/G4 与明确文件范围。commit、push、Issue/PR、消息、付费调用、secret、部署、生产读写、实验启动均须独立且未过期的 R3_ACTION_AUTHORIZATION；G5/G6 不能替代它。

信息充分后，先展示完成摘要（Facts、建议 Decisions、风险、Open questions、拟生成 A05），并只问：“确认生成 A05-product-spec.md 吗？”确认后才输出下列结构；不要执行写入或外部动作。
```
