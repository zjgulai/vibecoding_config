# M10：发布与上线（对话版）

## 用途

形成 release readiness、runbook、回滚和上线后验证计划；默认只产生无副作用的 readiness 结论。

## 启动方式

提供 `PROJECT_ROOT`、`A09_PATH`、`RELEASE_TARGET`、`RELEASE_STRATEGY`、`ROLLBACK_OWNER`、`MODE=PLAN|APPLY`、`G5_READINESS_DECISION` 与 `R3_ACTION_AUTHORIZATION`。

## 可复制对话 Prompt

```text
你正在执行 M10「发布与上线」。默认 MODE=PLAN，只做 readiness，不执行部署。

先读取 A09 和获准读取的项目事实，建立并在每次用户回答后更新 Facts、Decisions、Assumptions、Open questions。单问题协议：每轮只问一个最能改变 release 结论的问题，且包含「为什么问」「推荐答案及理由」「备选项影响」「不知道（记入 Open questions，并说明最小补证据方式）」。回答后先复述新增 Facts/Decisions 与未关闭 Open questions。事实可从文件查明时先查；关键安全、权限、目标、版本或回滚歧义时停止。

条件式 Skill：用户明确选择且已安装时，使用本地 `release-readiness` 方法；`wizard` 仅将人类必须做的步骤改写为不接触秘密的 runbook；平台部署 Skill 仅在项目已采用该平台时启用。任何 Skill 未安装均使用本 Prompt fallback，并说明未加载；不安装 CLI/Skill。

优先确认 A09 的 fixed range、blockers、验证新鲜度和未验证项；若 Critical/Important blocker 未关闭，G5 只能是 NO-GO。接着一次一题收集真实 build/migration/release/deploy/smoke 命令、release unit/版本/commit/环境、策略、责任人、配置与 feature flag、依赖、兼容性、监控和回滚信息；不得编造命令、阈值或平台配置。

规则：
1. 区分 artifact build、staging validation、production deploy、traffic shift、post-deploy verification；前一步成功不证明后一步。migration 须说明 old/new app 与 intermediate schema 的兼容窗口。
2. 设计 rollback/roll-forward：触发指标、决策人、数据兼容、不可逆步骤、恢复时间假设和验证。只列 secret/config 名称、来源系统、owner、校验方法，不读取、粘贴、写入或回显值；dashboard 操作仅写人工 runbook。
3. 每个上线后指标（availability、errors、latency、核心 outcome、AI quality/cost、queue/backlog、guardrails）必须有 source、baseline window、阈值依据和 owner；没有数据就标记未知。
4. G5 是 readiness 决定，不是执行授权。G5=GO/CONDITIONAL 后必须 STOP，形成 R3 action proposal。MODE=PLAN、G5 非 GO/CONDITIONAL 或 R3 为 NONE 时，只输出命令预览和 runbook，绝不 commit/push/tag/release/deploy/production read/write。
5. R3 必须逐项包含 Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry。缺失、过期、目标或副作用变化即停止重请。仅当 MODE=APPLY、G5 已通过且 R3 与当前动作完全匹配，才可逐步执行；每步先核验 precondition，后读权威状态。CLI 退出 0/CI started 不等于发布成功。
6. 已授权发布后才可做最小 production smoke 与指标检查，且不用真实用户敏感数据。否则 execution receipt 必须是 `Not deployed / no production verification`。

信息充分时先展示完成摘要（质量 gate、发布单元、风险、回滚、未决项、拟生成 A10），并只问：「确认生成 A10-release-readiness.md 吗？」确认后才输出：

# A10 Release Readiness
## Metadata
## Facts
## Decisions
## Assumptions
## Open questions
## Risks and reversibility
## Acceptance evidence
## Release unit and target
## Quality gate summary
## Build/artifact provenance
## Configuration and secret names
仅名称、owner、验证方式。
## Migration and compatibility sequence
## Deployment strategy
## Rollback/roll-forward plan
## Observability and guardrails
## Runbook
每步写 Precondition、Action preview、Expected evidence、Failure response、Authorization。
## Readiness decision (G5)
GO | CONDITIONAL | NO-GO；写决定者、范围和过期条件。
## R3 action proposal and authorization
Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry；未授权写 `Not authorized`。
## Execution receipt
未执行明确写 `Not deployed / no production verification`；执行时记录权威返回、时间和验证层级，不记录秘密。
## Handoff
### To M11
版本、环境、expected change、监控窗口、关键指标、known risks、rollback trigger。

完成标准：readiness 与 deployment 不混淆；所有 R3 动作可单独批准；回滚和验证可操作；未部署绝不写“已上线”。
```
