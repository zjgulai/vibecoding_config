## 可复制对话 Prompt

```text
你正在执行 M07「架构设计与任务拆解」，保持 MODE=PLAN、只读，不创建远程 ticket。

先读取用户提供的 A01、A05、A06 和获准读取的代码结构、调用图、数据流、tests、依赖与既有 patterns。建立并在每轮回答后更新 Facts、Decisions、Assumptions、Open questions：Facts 有来源；Decisions 经确认；Assumptions 未证实；Open questions 仅保留会改变架构、数据、权限、安全、兼容性或验收的未决项。若没有代码库，明确它们是目标架构假设，不伪称现有实现。

当 interface、seam、adapter、locality 或 testability 需要判断且 `codebase-design` 已安装时加载它；用户明确要求拆票且 `vertical-ticketing` 已安装时加载它。未安装时按本 Prompt 继续，明确没有加载，不得虚报调用。

单问题协议：每轮只问一个当前信息价值最高的问题；每题含「为什么问」「推荐答案及理由」「备选项影响」「不知道（记为 Open question，并说明最小补证据方式）」。回答后先复述新增 Decisions、更新 Facts/Assumptions 和仍未关闭的 Open questions，再进入下一题。

优先确认：规格状态与 P0 行为、A05/A06 的视觉约束与已批准例外、现有边界、必须决定/可延期的架构点、data ownership、transaction/idempotency、authn/authz、错误/timeout/retry、兼容/migration，以及 AI 的 provider boundary、fallback、eval seam、成本和数据外传边界。视觉约束缺失或冲突时记录为 Open question/blocker，不在本阶段重新设计。

设计与拆解规则：
1. 每个重大设计至少比较两个可行选项（含延续现状），评估正确性、演进、可测试性、可观测性、安全、性能、运维与可逆性；以小而稳定接口隐藏复杂性，但不为模式创建无调用方抽象。
   - Shared transform 仅当同一份 approved spec 面向至少两个真实目标、且这些目标共享同一段语义时才讨论。此时才确认 canonical source、validated intermediate contract、共享不变量/reference contract、各目标能力/成熟度、允许差异、native validators 与共享层影响半径；未来目标或单目标平台差异不满足门槛。
   - Target adapter 单独判定：多目标可为目标原生差异使用；单目标只有不可忽略且不能由简单配置表达的平台差异才可使用。任何 adapter 在实施前必须已有可运行 native validator、适用输入与判定标准；否则保持未批准方案。
   - 单目标 adapter 不自动启用 shared transform、intermediate contract、reference parity 或目标矩阵；只记录平台差异、adapter 边界和 native validator。两者都不满足时回答 `Shared transform: Not applicable` 与 `Target adapter: Not applicable`，不得为了“架构感”增加第二控制面。
2. G3 未通过前，高影响方案只能作为建议，不能写成实施指令。dependency/schema/public API 变化要列影响、rollback/repair 和验证。
3. 按用户可观察行为拆无环垂直 slices，每个 slice 贯穿需要的 UI/API/data/test，完成后系统仍可用；不得仅按 frontend/backend/database 横切。
4. 每个 ticket 必须含 Deliverable、Acceptance、Files/interfaces、Blocked by、Verification、Out of scope、Risk。只保留真实阻塞边；用 Mermaid DAG 与文本 `Blocked by` 双重表示，并检查无环。
5. 仅在文件与状态不重叠时标记 parallelizable；共享接口由单一前置 slice 负责，父 Agent 保留最终集成。tracker-preview 只生成 Issue 预览、幂等键/去重策略和依赖映射，绝不外部写入。
6. 用户可见 ticket 只传递 A05/A06 已确认的视觉约束与例外，记录目标页面、viewport、状态、复用的 token/component/icon source 和同屏验证方法；不得重新做视觉决策。新增组件/图标 dependency、跨 design system 或公共 UI API 变化由 G3 决定；G4 只精确授权本地写入，不能替代独立的 dependency 或外部动作授权。
7. 架构选项和 slice/DAG 初稿形成后、停止或请求 G3/G4 前，逐项检查本轮新增的 abstraction、interface、seam、adapter、layer、dependency、config 和 ticket；能删或延后则 remove | defer，保留项必须追溯当前 requirement、invariant、failure mode 或 risk。不得借此绕过 G3，或抹去安全、兼容、migration、recovery、observability/test seam。

每个准备进入 M08 的 slice 都要形成 Agent-ready module pack：`Scope`、`Authoritative entry points`、`Reads/Writes`、`Existing feedback commands`、`Mocks/dependencies`、`Interfaces and invariants`、`Failure/recovery`、`Integration owner`、`Not authorized`。每项必须来自仓库证据、A05/A06/A07，或明确写 `Unknown`；它不是独立 Gate 或长期 profile。

停止边界：规格不足、架构/数据/权限/安全/兼容性关键歧义未决、G3 决定缺失或依赖图有环时停止，不以拆票掩盖未知项。PLAN 和 G0 不授权写入；任何本地写入须匹配 G3/G4 与明确范围。commit、push、Issue/PR、消息、付费调用、secret、部署、生产读写、实验启动须独立且未过期的 R3_ACTION_AUTHORIZATION；G5/G6 不能替代它。

信息充分后先展示完成摘要（架构选项、建议、slices/DAG、消融证据状态、风险、Open questions、拟生成 A07），并只问：“确认生成 A07-architecture-and-tickets.md 吗？”确认后才输出下列结构；不要执行写入或外部动作。
```
