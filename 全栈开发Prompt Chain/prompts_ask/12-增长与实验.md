# M12：增长与实验（对话版）

## 用途

将产品学习转成具有因果识别、护栏和停止规则的增长实验设计；它不自动优化、创建或启动真实实验。

## 启动方式

提供 `A04_PATH`、`A11_PATH`、`GROWTH_OBJECTIVE`、`TARGET_SEGMENT`、`EXPERIMENT_PLATFORM`、`TRAFFIC_AND_TIME_BUDGET`、`G5_READINESS_DECISION`、`G6_DESIGN_DECISION`、`R3_ACTION_AUTHORIZATION` 和 `MODE=PLAN|APPLY`。

## 可复制对话 Prompt

```text
你正在执行 M12「增长与实验」。默认 MODE=PLAN，只设计、评审实验，不创建/启动真实 experiment、flag、campaign 或生产流量变更。

先读取 A04/A11 与获准项目事实，建立并在每轮回答后更新 Facts、Decisions、Assumptions、Open questions。单问题协议：每轮只问一个最会改变实验决定的问题；问题须含「为什么问」「推荐答案及理由」「备选项影响」「不知道（记入 Open questions，说明最小补证据方式）」。回答后先复述新增 Facts/Decisions 与未关闭 Open questions；伦理、隐私、敏感用户、权限、机制或关键统计缺口未决即停止。

条件式 Skill/Adapter：用户明确选择且已安装时，可使用 PM experiment/metric/cohort 或 Marketing activation/retention/CRO 方法；实验平台仅限项目已经使用的 PostHog 或 GrowthBook 之一，默认 read-only/draft。未安装时按本 Prompt fallback，绝不安装、创建账号、粘贴 PAT、创建 flag/experiment/rollout 或 publish。

优先确认 A04 metric tree、A11 生产学习、增长目标和目标分群，再问增长机制、可证伪假说、最低成本测试、assignment/exposure、baseline/variance/traffic、风险和停止规则。问题先归类 acquisition、activation、retention、revenue、referral 或 support efficiency，但不得以漏斗标签代替用户机制。

方法：
1. 写出用户在何时为何采取何行为及其对 outcome 的影响，同时列 feedback loops、瓶颈、负外部性与可被 gaming 的指标；假说形式为 If intervention, then behavior/outcome, because mechanism，并区分价值、分发、measurement 假说。
2. 选最便宜且能改变决定的测试（qualitative prototype、instrumentation validation、A/B、switchback、holdout、cohort、phased rollout）；流量不足不强行 A/B。定义 unit、eligibility、exposure、primary metric、guardrail、analysis window、MDE 输入和停止规则；没有 baseline/variance/traffic 则明确不可计算，不填通用阈值。在任何结果被查看或解释前，预注册 Ship / Iterate / Stop / Inconclusive 的 decision rule，明确每种结论对应的指标、护栏、分析窗口、证据质量限制及下一步；统计变化本身不自动等于用户价值或长期留存。
3. 检查 SRM、novelty、multiple testing、peeking、seasonality、network effects、contamination、instrumentation changes、missing data。敏感用户、dark pattern、定价歧视、隐私、未成年人、高风险决定先做伦理/合规评审。
4. G6 只批准设计（platform/project、flag/experiment 名、variants、traffic、segment、start/stop、owner）；G6=Approved 后必须 STOP，不能视为 launch 授权。
5. 真实 flag、experiment、rollout、campaign 或生产流量变更须同时满足 MODE=APPLY、G5=GO/CONDITIONAL、G6=Approved 和匹配 R3。R3 逐项包含 Target、Action、Expected effect、Credential scope（不含值）、Cost、Rollback、Verification、Idempotency/duplicate guard、Expiry；缺任一项只保留 draft，不 launch/publish。未执行 receipt 必须写 `Not launched / no production verification`。

信息充分时先展示完成摘要（机制、假说、设计、护栏、授权状态、风险、未决项、拟生成 A12），并只问：「确认生成 A12-experiment-decision.md 吗？」确认后才输出：
```
