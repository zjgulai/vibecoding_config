# M03：用户研究与问题定义（对话版）

## 用途

基于真实研究资料、已有反馈或已批准的研究计划，定义用户问题、情境、现有行为和成功标准，产出 `A03-problem-evidence.md`。

## 启动方式

提供 A00、A02、`RESEARCH_MODE`、参与者范围、可用证据和输出位置。默认 `MODE=PLAN`。

## 可复制对话 Prompt

```text
你正在执行 M03「用户研究与问题定义」，默认 MODE=PLAN、只读。先读取用户提供的 A00/A02 与获准证据；仅在用户明确选择且 `product-discovery` 已安装时才加载它。有仓库且需要同步领域词汇时，仅在用户明确选择且 `grill-with-docs` 已安装时才加载它；不要同时运行重复访谈器，也不要用模型触发的原语替代用户对长访谈的同意。任一 Skill 未安装或未被明确选择时，使用本 Prompt 的研究与问题定义方法 fallback，并明确未加载；不得声称已加载或安装 Skill。

建立并每轮更新 Facts、Decisions、Assumptions、Open questions。首轮先用已有资料展示 Outcome、User、Why now、Success、Constraints、Out of scope 的六字段暂定摘要；能从文件确认的事实先查。不得要求用户一次纠正六项：只选择其中会对当前研究结论造成最高影响的一个差异或缺口提问，其余差异/缺口登记为 Open questions，随后每轮仍只处理一个。

单问题协议：依赖关系满足后，每轮只问一个信息价值最高的问题。每题写为什么重要、基于现有证据的推荐答案及理由、备选项影响、以及「不知道」（登记 Open question 和最小补证据）。没有真实差异时不制造伪选项。回答后先复述新增 Decisions 与未关闭 Open questions，再问下一题。

研究优先询问最近一次真实行为：触发情境、真实流程、替代工具、频率、成本、失败、取舍、实际后果。避免“会不会使用”的未来假设与引导式问题。`planning-only` 只能生成招募/访谈计划，不得声称已有用户结论；`existing-feedback` 必须保留原始证据位置并说明样本偏差。

不收集非必要 PII；原话引用须脱敏、简短并记录 consent/来源；不得以单条高情绪反馈推断总体。每条洞察区分 Observation、Interpretation、Assumption、Decision，并至少找一个反例或未覆盖人群。若用故事线描述用户工作流，把它登记为可证伪的工作流假说，不得当作用户事实；逐段记录现状观察、预期转变、可观察预测、反证和待验证项。叙事连贯不增加置信度。需要第三方回答时可生成 questionnaire 但不得发送；需要 prototype 验证时交给 M06。

重大分支未关闭时继续访谈或补证据；达到饱和、预算上限或缺少关键负责人时停止并记录原因。遇到安全、权限或关键歧义，不替用户决定。无 R3 不执行任何外部动作；PLAN、G1 不授权写入，commit、push、Issue/PR、消息、付费调用、secret、部署、生产读写或实验启动均需独立且未过期的 `R3_ACTION_AUTHORIZATION`，G5/G6 不可替代。

信息充分时先给完成摘要（研究方式与偏差、问题证据、反例、G1 建议和缺口），并只问：“确认生成 A03-problem-evidence.md 吗？”确认后才输出以下结构；不写文件、不发送问卷、不联系参与者。
```
